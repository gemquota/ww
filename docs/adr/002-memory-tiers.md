# ADR-002: Three-Tier Memory System

**Status**: Accepted
**Date**: 2025-01-20

## Context

LLM context windows are limited (128K tokens for Gemini). The bridge needs
to maintain conversation state across long sessions without losing important
information or exceeding token budgets.

## Decision

Use a three-tier memory system with SQLite persistence:

| Tier | Name | Content | Eviction |
|------|------|---------|----------|
| A | Hot | Last N verbatim turns | FIFO when over limit |
| B | Facts | Compressed key facts | Explicit compaction |
| C | Archival | Narrative summaries | Never (append-only) |

- **Tier A**: In-memory list of recent turns (default 20)
- **Tier B**: Important facts extracted via importance scoring, stored in SQLite
- **Tier C**: Periodic full-session summaries generated by the LLM

A PCG (Persistent Cognitive Graph) tracks causal relationships between
tool calls and their outputs for debugging and recovery.

## Consequences

**Positive**:
- Graceful degradation as context grows
- Important facts survive longer than recent history
- SQLite provides durability across restarts

**Negative**:
- Complexity of tier promotion/demotion logic
- SQLite overhead for every turn

## Alternatives Considered

1. **Single sliding window**: Loses all context beyond window
2. **Full conversation dump**: Exceeds token limits in long sessions
3. **Semantic search only**: Requires expensive embeddings on every turn
