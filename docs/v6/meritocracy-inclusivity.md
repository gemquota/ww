# Meritocracy vs Inclusivity — V6-C1#4

## Principle
This project values both merit-based advancement AND inclusive participation. 
They are not mutually exclusive when designed intentionally.

## Practices

### Inclusive Meritocracy
- **Low barrier to entry**: Good first issues, mentorship, documentation
- **Clear advancement paths**: Defined criteria for committer/maintainer roles
- **Multiple contribution types**: Code, docs, review, design, community support
- **Recognition**: All contribution types are equally recognized

### Anti-Patterns to Avoid
- Requiring deep domain knowledge for any contribution
- Unwritten rules that only long-time contributors know
- Review processes that favor familiarity over correctness
- Burnout culture from over-rewarding volume over quality

## Metrics
- Demographics diversity in contributor base
- First-time contributor experience (survey)
- Time from first PR to committer role
- Retention rate by contribution type
